How the mazes are built

    
    
      
  1. Draw a random spanning tree over a W×H grid: a perfect maze in which every pair of cells is joined by exactly one path.
    2. 
      
  2. Place the start S and the goal G.
    3. 
      
  3. Pick one wall segment e on the unique S→G path. Closing it splits the maze into a part A containing S and a part B containing G.
    4. 
      
  4. Pick loops extra passages X plus one more passage w, all joining two cells of the same part.
    5. 
    

    
Solvable = tree + X. Unsolvable = tree − e + X + w.

    
The two versions of a seed form a minimal pair: identical number of walls, identical S and G, and they differ at exactly two wall segments. Nothing local gives the answer away: a classifier has to trace connectivity through the whole maze, the same computation Pathfinder demands of two dashed contours. The only global difference is that the unsolvable maze has one more cycle than the solvable one.

    
Difficulty

    
    
      
  • Grid size and placement (far maximises the path length) set how long the path to trace is.
    • 
      
  • Cut position sets the size of the two disconnected parts. balanced makes both large, so the missing link cannot be found by inspecting a small pocket around S or G; near the start creates small pockets that are easy to spot.
    • 
      
  • Loops add alternative routes and remove the dead-end texture of perfect mazes.
    • 
      
  • Algorithm changes the texture: backtracker gives long winding corridors, kruskal and prim give many short branches.
    • 
    

    
Reproducibility

    
Everything is seeded. The Python package in this repository (mazes/) reproduces the browser's mazes bit for bit from the same seed and parameters, so an image you look at here can be regenerated in a dataset with scripts/make_dataset.py, and model runs from scripts/eval_model.py use the same prompt as the Model tab.
